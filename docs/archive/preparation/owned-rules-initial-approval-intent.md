# Initial approval intent

This is an inactive, opt-in composition for the closed disposable owned-read
service. It separates the initial human wait from execution authority without
rebinding an old callback or extending an expired action. It does not mount a
production guard, change generic provider behavior or enable durable recovery.

The trusted producer reserves the exact original delivery and invocation before
creating a historical review preview. The preview exposes only its action,
currentness assertion, review provenance and policy evaluation. Its executor
always refuses; it has no authorization, dispatch or delivery-binding method.
The controlled strict policy cannot qualify this preview as executable, and its
actual indeterminate result is recorded without promoting it to a passed review.

The source retains a separate pending-execution capability with canonical resource
scope, actual current policy, physical lease identity, live credentials, workspace
binding and cancellation checks. The protected owner authenticates the original
persistence review while its preview is live, then retains its exact protected
seal and current reviewer checks independently from the old action expiry. This
does not change the legacy persistence verifier or the meaning of its records.

The displayed review handle still expires. Refreshing it reuses the same private
reservation and historical proof, rather than creating another executable
lineage. Both pre-choice and actual accepting checks require that capability,
the protected historical checker and current authority. RPC fields describing a
pending intent and its execution window cannot create those capabilities.

Only a successful final original acknowledgement can redeem the reservation.
The service then obtains current execution authority, captures a distinct action,
registers its actual facade and reruns mandatory policy and review checks. The
individual action window remains at most 60 seconds and is clipped to the actual
remaining lease and credential lifetime. A historical human answer cannot bypass
a new required review, denied policy, revoked credential or expired new action.

Prepared reservations, previews, successful captures and failed construction
tombstones share one bounded invocation budget. Ordinary capture cannot redeem a
reserved key. Duplicate and reentrant attempts share one result; denial,
cancellation, failed acknowledgement, retirement and uncertainty cannot reopen an
attempt. Save still publishes only an explicitly reviewed standing grant. It
answers no query, performs no resource read and permanently retires the original
preview and reservation.

The prepared path retains and drains already-started owned work before releasing
its lease or removing its fixtures. Closing publishes its shared drain promise
before invoking abort listeners. Cleanup errors remain errors. Cancellation after
the physical read cannot prove that no read occurred; the receipt must preserve
execution uncertainty and prevent replay. The generic legacy fence is unchanged.
An execution result can settle before all tracked work; its owner must await
`closeAndDrain()` before returning or releasing the enclosing lifetime. Tracking
covers returned promises, not detached tasks started by a trusted callback after
it has already reported completion.

The renderer requires a coherent pending-intent/window pair before offering fresh
checks for an unavailable execution preview. It preserves explicit failed-review,
coverage, disclosure, unsupported-path, staleness, expiry and revocation vetoes,
and still invokes only the owner's opaque choice closure. It explains that the
window starts after approval and current checks may refuse execution. Save and
Deny retain separate behavior. Older strict clients may reject the additional
reply fields; matched contracts or explicit negotiation remain necessary before
activation. An older server still receives the conservative existing UI behavior.

## Evidence scope

The focused controls are in:

- `packages/engine/test/post-approval-owned-read.test.ts`: private redemption,
  preview non-execution, retirement, reentrancy, cancellation and owned cleanup.
- `packages/cli/test/initial-approval-owned-read/initial-approval.test.ts`: actual authenticated
  bridge choices, a real-clock wait beyond preview expiry, stale/duplicate handles,
  final acknowledgement, Save isolation and protected proof/authority mutation.
- `packages/agents/test/acp-permission-lifetime.test.ts`: an ended turn's late
  answer or failure cannot authorize or cancel a later turn on the same session.
- The renderer's scoped-rule choice and port tests: coherent presentation fields,
  existing vetoes, opaque owner calls and distinct Save/Deny behavior.

The disposable integration supervisor's coverage and reviewer are explicit test
assumptions. Its intercepted bounded file read is not independent syscall effect
proof. Prior frozen observer artifacts retain their original source and physical
image identity; none attests this candidate's exact bytes. No new observer run,
production activation, release or deployment is claimed.

The original query must still belong to a genuinely live owner. This candidate
does not keep an ACP callback alive after turn timeout, cancellation, disconnect
or process loss. See [provider continuation](owned-rules-provider-continuation-boundary.md)
for the current fail-closed behavior and unresolved durable lifecycle choices.
