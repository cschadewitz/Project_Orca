## Findings

### D10-01 — The guarded MCP launcher cannot use the access decision's least-privilege read-only grant
- **Doc:** `docs/preparation/private-mcp-access/decision.md:57-64` proposes the initial credential: "only `runs.read`, `artifacts.read` and `workflows.read`" with a finite expiry. `connection-design.md:187-195` lists Launch/preflight, cancel/resume and answers as **Absent** for the first probe. Neither doc records that this envelope was retired.
- **Code:** `tools/deploy/private-mcp-service/credential-policy.js:6-14,114-120` accepts exactly two envelopes: `scoped-six`, which adds `runs.start`, `runs.control` and `inputs.answer`, and `workspace-plan-eight`. Any other permission set fails with `permissions`, and `validateCredential` (`:226`) requires an exact set match. So the guarded launcher refuses the read-only credential, and an operator has to issue a write-capable credential to use it. `service-supervision.md:21-26` documents only those two envelopes.
- **Variance type:** contradicts-design / doc-conflict
- **Severity:** Medium (least-privilege posture differs between the access decision and the built credential tooling)
- **Confidence:** High
- **Suggested resolution:** decide. Either add a reviewed read-only `scoped-read` policy to `credential-policy.js`, or add a dated note to decision.md and connection-design.md that the approved envelope became `scoped-six`/owned.
