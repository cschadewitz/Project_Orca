### D6-02
- **Verdict:** CONFIRMED (one sub-bullet is weaker, see below)
- **Adjusted severity:** High. Rule 10 is binding, and the drop happens on common keyboard paths. With focus on `body`, `scopesFrom` (`keyboard-map.ts:207-215`) yields only `global`, so after ⌘2 or `G` the destination's `J`/`K`/`Enter` do nothing until the person Tabs or clicks back in.
- **Evidence:**
  - **Surface switch.** `PrimaryPane` is re-keyed per surface (`App.tsx:258-259`). `selectSurface` and `navigate` only set state (`App.tsx:162-186`), and nothing in `chrome/` or `App.tsx` calls `.focus()` except the mismatch dialog. `<main tabIndex={-1}>` (`chrome/primary-pane.tsx:38`) is never focused. A nav click keeps focus because the sidebar button survives. ⌘1–⌘6 (`chrome/use-chrome-shortcuts.ts:24-31`), crumbs, `G`, and palette jumps all drop focus. For palette jumps, `use-command-palette.ts:43` restores focus only to a still-connected element, and that element is then unmounted.
  - **Panel close.** The docked panel's close button (`chrome/docked-panel.tsx:50`), `Esc` through `useTransientLayer` (`App.tsx:232`, `layers-context.tsx:38-53`, no restore) and ⌘\ just unmount the panel.
  - **Mismatch dialog.** It focuses itself on open (`chrome/connection-banner.tsx:129-131`) and restores nothing on close. `daemon-connection/dialog.tsx:26-33` shows the restore pattern it should use.
  - **Last Attention card.** It returns at `index < 0` (`attention/attention-surface.tsx:104-106`) and the section unmounts. The test skips that case (`test/attention-surface.test.tsx:97`, `if (n < 5)`).
  - **Inline cards.** They are removed with no handling (`attention/inline-asks.tsx:77-95`). Electron/Chromium focuses a clicked button, so the Answer button's focus goes with the card.
  - **New-ask sub-bullet (weaker).** Focus does not fall to the body there. It moves to whatever card now sits at the old index (`attention-surface.tsx:104-113`), which happens only when the new ask sorts above the focused card (a permission ask arriving while the person is on a gate). That breaks rule 10's "stays where they put it", not "never to the page body".
- **Fix note:** On a surface switch, focus the new surface's primary list or region (something carrying its key scope), not just `<main>`, so the keys work on arrival. Track the focused card by input id, not by index.

- **Fix note:** Give **Always deny** the default tone with no confirm. Destructive options take the default tone too: they are marked by being last and unbound (plus the consequence line), not by colour. Only the Diagnostics delete needs the armed Keep / ✕ Confirm row.

### D6-11
- **Verdict:** CONFIRMED
- **Adjusted severity:** Medium. Failed runs are on the landing surface, and error messages are routinely long. A long one overflows the row and pushes the time out of view. The failed row cannot be opened (D6-13), so the whole message has nowhere else to be read.
- **Evidence:**

- **Fix note:** Make the message a shrinkable cell (`min-width:0`, ellipsis, whole text in `title`), and add `title={run.name}` to the cut name (both the Failed and Running rows).
