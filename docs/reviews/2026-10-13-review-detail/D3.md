### D3-01 — MCP retry key limit is wrong in `mcp-operator.md` and contradicts the production contract
- **Doc:** `docs/mcp-operator.md:151-152`: "`retry: {idempotencyKey}` is required by MCP (maximum 200 characters)". The other doc says the opposite: `docs/mcp-operator-production-contract.md:11`: "Its limit is 1–128 UTF-8 bytes, never 200 characters."
- **Code:** `packages/protocol/src/admission-retry.ts:6-9` defines `RetryKeySchema` as 1–128 UTF-8 bytes. MCP `retry` uses it (`packages/protocol/src/operator-mutations.ts:18`). A key of 129–200 characters, or a shorter key that is over 128 bytes once multibyte characters are encoded, fails tool-argument validation with `PROTOCOL_MESSAGE` (`packages/integrations/src/mcp/server.ts:209-211`).
- **Variance type:** doc-conflict and stale-doc
- **Severity:** Medium. This is a client-facing MCP contract. The published JSON schema does not express a `refine`, so clients rely on the prose.
- **Confidence:** High
- **Suggested resolution:** Update `mcp-operator.md` to say "1–128 UTF-8 bytes".

### D3-02 — `PROTOCOL_VERSION` is listed as a wire code, but the daemon refuses a version mismatch with `NOT_SUPPORTED`
- **Doc:** `packages/protocol/README.md:37-38` lists `PROTOCOL_VERSION` among the codes on the wire. Line 166 says "Major versions must match before normal client operation". The `hello` section (154-176) never says how an incompatible `hello` is answered.
- **Code:** `packages/daemon/src/methods.ts:366-375`. The daemon's `hello` throws `OrcaError("NOT_SUPPORTED", "client speaks protocol …", {client, daemon})` when `isCompatible` fails, and no daemon path emits `PROTOCOL_VERSION`. That code is only made up on the client side: `packages/app/src/client/daemon-client.ts:600`, `packages/integrations/src/mcp/backend.ts:118`, `packages/cli/src/commands/revisions.ts:126`. Line 37 also calls the protocol-only codes "an `OrcaErrorCode` from `core`", but they are protocol-only (`errors.ts:9,25,47`). The three `AUTH_*` codes are left out of that sentence.
- **Variance type:** undocumented and contradicts-design. The code comment in `errors.ts:3-5` says the protocol adds a "version mismatch" code.
- **Severity:** Medium. A third-party client branching on `PROTOCOL_VERSION`, as the README implies, never sees it from the daemon.
- **Confidence:** High
- **Suggested resolution:** Decide. Either have `hello` throw `ProtocolFault("PROTOCOL_VERSION")`, or document that a mismatch answers `NOT_SUPPORTED` with `details.client` and `details.daemon` and that `PROTOCOL_VERSION` is client-synthesized.

## Confirmed consistent

**Transport and envelopes**
- Envelope shapes and `parseMessage` (`envelope.ts`) match the README.
- `/health` is unauthenticated and answers exactly `{ok:true}`.
- `socketUrlFor` and `SOCKET_PATH = "/socket"` match.
- `/rpc` re-authenticates after the body is read; operation checks run before params; invalid params give `PROTOCOL_MESSAGE` with Zod issues.

**Security: transport and credentials**
- Token mode: Bearer header or the `orca.v1` + `orca.bearer.<token>` subprotocols; the daemon selects `orca.v1` and never echoes the bearer protocol; two credentials count as malformed.
- Error responses:
  - missing credential → 401 `AUTH_REQUIRED`
  - malformed, unknown, mismatched, expired or revoked → identical 401 `AUTH_INVALID` with no details and a `WWW-Authenticate` header
  - URL credential keys → 401
  - Origin, Host, proxy-bypass and non-https proxy → 403 "not permitted"
  - transport refusals use `id: 0`
- Sockets re-check credentials per message, per notification and every `revalidateMs` (default 5000), and close with code 4401 plus a `connection.closed` audit entry.
- `startDaemon` refuses to start without an auth policy. Loopback-unauthenticated mode is refused off loopback. A non-loopback bind needs IP `trustedProxies`. `X-Forwarded-Proto` uses the last value; `X-Forwarded-For` uses the right-most entry, for audit only.
- CLI `serve` defaults to `127.0.0.1:6722` and supports `--read-only`, `--unauthenticated-loopback`, `--trusted-proxy` and `--allow-origin`.
- Credential format: `orca1.<12-char id>.<43-char/256-bit secret>`, with SHA-256 stored at rest.
- `credentials.json`, `ownership.json` and `local-client.token` are written 0600 through an atomic temp-file rename. The auth dir is created 0700 with a `.gitignore` of `*`. `audit.jsonl` is created 0600 at construction, before the daemon listens.
- The file lock covers reload, mutate, persist and token publication. A damaged credentials file fails at startup and refuses every credential at runtime.
- Bootstrap revokes every previous bootstrap credential.

**Security: authorization**
- Presets match: owner excludes `host.telemetry.read`; operator, viewer and client match their docs. Workspace-wide permissions are refused for restricted scopes at issue time and again at check time.
- The permission matrix matches `OPERATIONS` row for row, including the audit column (mechanical diff).
- Notification gating matches the table, and `event.appended` artifact projection matches.
- `artifactEvent` covers `artifact.*`, `step.inputs` and `plan.signals.rejected`. Journal projection matches.
- Gate decisions check `permissions.grant` first for `always`. `hello` filters `methods` and `capabilities` and hides `storeDir` without `config.read`.
- An invisible run subscription is answered silently with `replayed: 0`.

**Read-only mode**
- `--read-only` drops the `runs.control` capability and omits every control method, plan write, `config.set`/`config.apply`, request, admission, continuation and revision method, and all ten operator mutation aliases.
- `config.get`, the agent methods, `maintenance`, the operator reads and preflight, and the template and draft reads remain.

**Push channel and plan**
- 11 notification methods; 6 log-derived ones.
- `agent.changed`, `config.changed` and `plan.changed` go to store-wide subscriptions only.
- `since` requires `runId`. Agent output batches at 100 ms. `subscribe` over `/rpc` answers `NOT_SUPPORTED`. `workflows.changed` is emitted with `config.changed` on apply.
- Five `CONTROL_ERROR_CODES` and three `AUTH_ERROR_CODES`.
- Plan write schemas; `PlanOrigin{human, daemon}`; `PLAN_INVALID`.
- The live answer refuses `resume:false` with `NOT_SUPPORTED`. The `live-input.ts#L15-L18` and `control.ts#L46-L48` anchors are correct.

**Maintenance (README, partial)**
- The legacy `maintenance` prepare/resume token semantics, the "Another updater owns admission" refusal, and the `hello`/`subscribe`/`unsubscribe` exemptions match.

**MCP operator**
- 27 tools (`OPERATOR_TOOLS`) match the `mcp-operator.md` table plus `get_daemon_resources`.
- Authority is checked before argument validation. Page default 50, max 100. Result cap 256 KiB, command cap 64 KiB, artifact text 16 KiB. Rows over 12 KiB become `oversized-item`. Cursors are HMAC-signed.
- The decision union is strict, has no `always`, and requires seven live fields. Cancel `reason` max is 2000.
- `orca mcp` requires an explicit endpoint and token env and discovers before opening stdio. The HTTP handler requires a fixed HTTPS origin and `/mcp`, and is built per request.
- SDK pins: server 2.3.0, client 2.2.0.
- The five read and preflight operations are mounted by `serve`. Production-contract envelopes match `OperatorMutationContracts`; `submitRetry` and `admitRetry` exist with the stated signatures.

**Host resources**
- All limits in `host-resources.md` and the access policy match the code:
  - timing: refresh 5 s, expiry 15 s, source deadline 250 ms, collection 1 s
  - read sizes: 65,536-byte cap with a 65,537-byte buffer
  - output: snapshot 32,768 bytes, 12 warnings, 1,000 workstream records
  - concurrency: 4 outstanding operations
  - worker limits: 16/4/1 MiB; at most 8 cgroup path components
  - warning thresholds: 0.9, 0.1 and 1,048,576
- The worker is unref'd. No preset grants `host.telemetry.read`. The mount needs token auth plus identity plus an injected source, and the CLI does not inject one.
- The workstream permission-denied and unavailable states match. The serialization-time publication fence matches.

**Integrations**
- ACP facade option ids, categories and defaults match. `loadSession:false` and `embeddedContext:true` match.
