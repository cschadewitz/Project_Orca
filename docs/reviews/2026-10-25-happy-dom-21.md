## Behavior and regression boundary

Happy DOM moves from `^20.14.5` (resolved 20.14.5) to `^21.0.4` (resolved
21.0.4). Node's supported floor is compatible and Vitest 5.0.5 declares
Happy DOM peer `*`. No adapter or application setting enables JavaScript,
external CSS or iframe-page loading. ORCA's theme harness and appearance
fixtures inject local CSS inline and need no loading opt-in.

Four bounded tests exercise both Vitest's actual Happy DOM adapter and the
standalone `Window` used by appearance tests. They check disabled settings,
classic/module script and inline-handler nonexecution, plus a live loopback
recorder that receives its control request but no stylesheet, CSS preload or
iframe-page request. Each fixture cleans up its nodes, connections and
standalone window. They do not execute exploit payloads or restore old loading
behavior. Happy DOM emits expected disabled-resource diagnostics.

Happy DOM remains component/state test infrastructure. It cannot establish
real Chromium layout, Electron preload/CSP, focus, native persistence or
platform screenshot acceptance. Existing Electron suites are intact.
