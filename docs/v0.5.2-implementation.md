## Release-label audit

The fetched issue labels are suggestions about work, not release decisions. Only #258,
#254 and #228 already carried `release:none`; those remain appropriate for internal
tooling/test commits. #228 also required a user-visible Windows demo file-URL correction,
so a combined PR containing that fix should be `release:patch`. #134 similarly includes
a corrected Windows permission path boundary, so its combined PR is patch work. None of
the other 26 issues carried a release bump label at fetch time. Use `release:none` for
#109 and the verified documentation disposition of #119; use `release:patch` for the
remaining behavioral corrections. No minor feature scope is requested or implemented.

Patch classification depends on preserving readable existing execution data and failing
safely where old ownership protocols cannot cooperate. The compatibility contract is in
[ownership handling](v0.5.2-ownership-compatibility.md); it must be reviewed together with
the lease changes. No new decision outcomes, Plan modes, workflow editor, persistent agent
sessions or v0.6 selection features are introduced. #138's optional nested plan expansion
is explicitly not claimed complete.

Claim recovery keeps child execution and scheduling consistent: a missing child can become
pending directly, while an unowned created/running child is durably cancelled under its
execution lease before its item is reset for dispatch. State is checked again under the
lease, so a child that parks during recovery remains paused/waiting. Live interpreters and
human-parked children remain protected; terminal child results retain their actual outcome.
Projection repair and its journal record precede claim deletion under the claim mutation lock.
