# Native Mac delivery: source audit

Preparation for [#402](https://github.com/cschadewitz/Project_Orca/issues/402),
under [#385](https://github.com/cschadewitz/Project_Orca/issues/385).
Audited on **2026-10-02**, after fetching `origin/main`, at source commit
**`7abc2342aa672ee9d2f10d565ca4f8eb546184df`**. All repository paths below refer
to that commit, not a peer branch or a released binary. This is a source audit;
no installer, Apple account, keychain, repository secrets or physical Mac was inspected.

Read next: [delivery design](delivery-design.md), [owner prerequisites](prerequisites.md),
[artifact contract](artifact-contract.md), [implementation handoff](implementation-handoff.md).
Only this preparation directory is changed. Parent delivery acceptance remains open.

## Existing foundations and gaps

| Area                  | What the source establishes                                                                                                                                                                                                                                                                                                                                                                   | Source at the audited commit                                                                                                                                                                                                             |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Packaging             | `appId: dev.orca.desktop`, product `ORCA`, `${productName}-${version}-${os}-${arch}.${ext}`; separate x64 and arm64 DMG and ZIP targets, no universal target. Output is `packages/app/dist/release`.                                                                                                                                                                                          | [electron-builder.yml](../../../packages/app/electron-builder.yml), `appId`, `artifactName`, `mac.target`                                                                                                                                |
| App contents          | Compiled `dist/**/*` and package metadata go into the app; daemon, release output, declarations, build state and maps are excluded from that file set. Production dependencies are included by the builder.                                                                                                                                                                                   | [electron-builder.yml](../../../packages/app/electron-builder.yml), `files`                                                                                                                                                              |
| Daemon contents       | esbuild consumes the built CLI and emits `dist/daemon/orca-daemon.mjs`, targeting Node 22, with workspace dependencies bundled. Optional `ws` accelerators remain external. Only `.mjs` is copied to `Contents/Resources/daemon/`; the source map is not shipped.                                                                                                                             | [build-daemon.js](../../../packages/app/scripts/build-daemon.js), [electron-builder.yml](../../../packages/app/electron-builder.yml), `extraResources`                                                                                   |
| Daemon runtime        | `findBundledDaemon` resolves the resource; `startOnce` spawns Electron's `process.execPath` with `ELECTRON_RUN_AS_NODE=1`, loopback binding and workspace cwd. Startup uses `LocalDaemonToken` and an authenticated `hello`. This does not require a second installed Node runtime.                                                                                                           | [daemon-process.ts](../../../packages/app/src/main/daemon-process.ts), `findBundledDaemon`, `startOnce`, `helloAnswers`; [index.ts](../../../packages/app/src/main/index.ts)                                                             |
| Signing               | `mac.identity: null` and `mac.notarize: false` deliberately disable Developer ID signing and notarization. No repository-owned entitlement plist or explicit hardened-runtime policy is configured; `packages/app/build/` does not exist in this tree. Tool defaults or an ad-hoc architecture signature are not Developer ID evidence. Actual output signatures/entitlements are unverified. | [electron-builder.yml](../../../packages/app/electron-builder.yml), `mac`, `directories.buildResources`; tracked tree inventory (`git ls-tree -r HEAD packages/app`)                                                                     |
| Toolchain             | Lock resolves Electron 44.4.5, electron-builder/app-builder-lib 26.15.3, `@electron/osx-sign` 1.3.3 and `@electron/notarize` 2.5.0. Declared ranges are not the installed version proof.                                                                                                                                                                                                      | [pnpm-lock.yaml](../../../pnpm-lock.yaml), [app package](../../../packages/app/package.json)                                                                                                                                             |
| Release version       | Root is `0.6.0`; app package remains `0.1.0`. CI overrides app metadata with the root version, while `build-daemon.js` embeds the root version in `__ORCA_VERSION__`. `ORCA_VERSION` uses that substitution or the root manifest.                                                                                                                                                             | [root package](../../../package.json), [app package](../../../packages/app/package.json), [build-daemon.js](../../../packages/app/scripts/build-daemon.js), [CLI commands](../../../packages/cli/src/commands/index.ts), `ORCA_VERSION`  |
| Version mismatch risk | The reusable desktop workflow accepts an arbitrary `inputs.version`, but the daemon bundler still reads the root manifest. The release caller passes the root version consistently; other callers could stamp mismatched app/daemon versions. A future signed lane must refuse this mismatch.                                                                                                 | [desktop.yml](../../../.github/workflows/desktop.yml), `The version to stamp`; [release-publish.yml](../../../.github/workflows/release-publish.yml), `check`, `desktop`                                                                 |
| Protocol              | The source protocol is `{major:1, minor:9}`. `hello` reports `protocol`, `orcaVersion`, capabilities and optional process/store metadata, not a source SHA. Store compatibility currently names `protected-execution-v2`; these are baseline facts, not frozen future release values.                                                                                                         | [version.ts](../../../packages/protocol/src/version.ts), [handshake.ts](../../../packages/protocol/src/handshake.ts), `HelloResultSchema`; [release-compatibility.json](../../../release-compatibility.json)                             |
| Build identity gap    | Publication resolves one source SHA and passes it to build/check jobs. The packaging/bundling configuration does not yet emit the signed in-app identity or Mac checksum/evidence manifest proposed here. A version string alone cannot identify a rebuild.                                                                                                                                   | [release-publish.yml](../../../.github/workflows/release-publish.yml), `The commit being released`; [electron-builder.yml](../../../packages/app/electron-builder.yml); [build-daemon.js](../../../packages/app/scripts/build-daemon.js) |

## CI and distribution evidence boundaries

| Existing path           | What it proves from source; what remains missing                                                                                                                                                                                                                                 | Source                                                                                                                                                                     |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Desktop workflow        | Manual dispatch/reusable workflow, frozen install, Node 24, build and daemon bundle on Linux/macOS/Windows. Mac uses moving `macos-latest`, with both Mac architectures requested. A runner label is not evidence of native arm64 execution.                                     | [desktop.yml](../../../.github/workflows/desktop.yml), triggers, matrix, Package                                                                                           |
| Standalone daemon probe | Runs the bundle under runner Node before packaging and looks for `"ok":true`. It sends no Authorization header, although current `serve` defaults to token auth. This is a source-level incompatibility to repair through the workflow owner; no CI failure was reproduced here. | [desktop.yml](../../../.github/workflows/desktop.yml), `The bundled daemon answers hello`; [CLI commands](../../../packages/cli/src/commands/index.ts), `serve`, `authDir` |
| Packaged launch         | The packaged-app startup step is Linux-only. Mac packaging and standalone Node startup cannot prove launch of the signed Electron app or its child process.                                                                                                                      | [desktop.yml](../../../.github/workflows/desktop.yml), `The packaged app starts its own daemon`                                                                            |
| Smoke/type proof        | Separate Electron smoke and cross-platform type-proof checks; publication depends on them. They use development/build routes, not a downloaded signed Mac candidate under Gatekeeper.                                                                                            | [app-smoke.yml](../../../.github/workflows/app-smoke.yml); [RELEASING.md](../../../docs/RELEASING.md), Release type proof                                                  |
| Upload/publication      | Packaging uses `--publish never`; CI uploads `.dmg`/`.zip` in `desktop-macos` (7 days standalone, 14 with a supplied ref). Release waits for checks/builds/smoke, stages a draft then publishes. No Apple secret forwarding, signing or notary gate exists in these workflows.   | [desktop.yml](../../../.github/workflows/desktop.yml), Upload; [release-publish.yml](../../../.github/workflows/release-publish.yml), `desktop`, `publish`                 |
| Asset validation        | Collision checks and Windows feed version/SHA-512/blockmap validation exist. There is no corresponding required Mac pair, SHA-256 manifest, signature or ticket check.                                                                                                           | [release-assets.py](../../../tools/deploy/release-assets.py), `verify`                                                                                                     |
| Private delivery        | Docs describe private GitHub releases and an optional authenticated HTTPS feed. The feed publisher requires Windows channel metadata. Host provisioning and invite access are unknown; the existing code does not establish a Mac browser download service.                      | [UPDATING.md](../../../docs/UPDATING.md), Private feed and Release/feed provisioning; [publish-feed.py](../../../tools/deploy/publish-feed.py)                             |
| Updating                | The driver returns undefined unless packaged on Windows x64/arm64. This handoff must not promise Mac automatic updates.                                                                                                                                                          | [update-driver.ts](../../../packages/app/src/main/update-driver.ts), `updateDriver`                                                                                        |
| User instructions       | Existing release notes document unsigned Mac delivery and a quarantine workaround. That workaround is not acceptable for the invited beta; the parent must replace those instructions only after verified signed delivery.                                                       | [RELEASING.md](../../../docs/RELEASING.md), Signing and notarisation are not done                                                                                          |
