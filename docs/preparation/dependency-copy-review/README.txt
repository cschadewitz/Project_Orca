Review-only dependency copier

This standalone Python standard-library library copies previously inventoried output
trees exclusively into independently allocated regular files. It has no CLI entry
point and performs no Git, package-manager, service, network or orchestrator action.
There is no implicit real-root operation. Only test_copier.py invokes copying, on
synthetic private fixtures, using:

    python3 -B test_copier.py

Place TMPDIR in an existing private disk-backed fixture area. Tests retain their
fixtures and partial outputs. They do not execute copied shims or package code.

Copier contract

The caller provides canonical nonoverlapping source/destination roots and a private
contract: trees (nonoverlapping relative output directories), entries (path, mode,
kind; file bytes/sha256 or symlink target), shims (reviewed path, before_sha256,
spans, unchanged_bytes_sha256, relative_target, header_sha256), shim_count,
prefix_count, and metadata (historical-file paths and unchanged SHA256 values).
The contract is an authority supplied by the caller, not generated by the copier.
Private receipt/mapping material must never be committed with these files.

plan() checks complete inventories, hashes/modes, unique regular inodes and nlink=1,
all directory parents with O_NOFOLLOW, link containment including proposed outputs
and untouched workspace targets, absence of every destination output tree, exact
recognized shim templates and mapping spans, and preservation of historical metadata.
Only recorded source-root prefixes in both NODE_PATH branches and the final target
marker change. The relative executable target and every other byte remain identical.
Inherited NODE_PATH is intentionally preserved; actual readiness commands must unset
NODE_PATH. Historical metadata keeps its original bytes and is not bootstrap proof.

copy_exclusive() rechecks before writing, uses O_EXCL and newly allocated regular
files (no hardlinks/reflinks), descriptor-relative no-follow parent access, original
modes and relative link targets, fsync, then full destination/source comparisons.
Existing/partial outputs are refused, never overwritten or resumed. Any failure
retains partial outputs for local evidence. Capture the exception and inventory in
the caller's private receipt; this library does not publish evidence or delete files.
It does not preserve timestamps/xattrs; bytes, mode bits and link text are its contract.

Before a real invocation

Independent review must approve these immutable helper bytes. The owner must freshly
bind the destination to the assigned run, original provisioning receipt, ready record,
Git registration, branch, base/HEAD, clean tracked/index state and unanswered gate;
verify the private inventory/proposal/contract hashes and establish supported write
access. A ready marker alone is insufficient. The caller must exclusively own both
roots during the operation: this library does not acquire daemon/worker locks, prove
quiescence, authenticate a run or substitute for its access policy. Replaced root
names and concurrent mutation are outside that ownership precondition; detected
file/directory drift fails with evidence retained. Never bypass a denied write.

Relocation templates

relocation.py preserves the byte recognizer from the reviewed fixture proposal,
with its three exact templates extracted from the reviewed public pnpm generator:
https://github.com/pnpm/pnpm/blob/9502f3c457717dae3a4ddbf4315a8c4aee16fdb4/pnpm/crates/shim/src/sh.rs
No real shim bytes, package payloads, mappings, private paths, run identifiers or
provisioning records are included. Synthetic shims are generated only for fixtures.

Execution coverage

Synthetic results cover owner-task local Linux/Python filesystem behavior in task-temp.
They establish neither real destination readiness nor the future worker sandbox,
native module load, capacity, inherited environment or loopback access. Root-local
checks require separately established access and completed reviewed copying, with
NODE_PATH unset and optional compile caching disabled. They must report their actual
execution profile; owner-session passes do not establish worker-profile behavior.
Nothing here answers a gate, starts an agent, restarts a service or admits a run.
