# ORCA iOS companion research

Draft for Casey and Cal, **3–4 October 2026**. Recommend an **iPhone app in SwiftUI**, backed by a small authenticated mobile facade over ORCA's existing services. Start with one enrolled host over a private VPN, generic notifications that can mirror to Apple Watch, and explicit phone review. Keep execution, authorization and durable command receipts on the host. A phone should make a pending decision understandable and safe to act on; it should not reproduce the desktop workspace.

This is research, not an accepted implementation or rollout plan. No app, credentials, infrastructure, device enrollment or notifications are created. The companion documents cover [architecture and security](architecture.md) and [delivery, costs, issue mapping and acceptance](delivery.md). Platform facts below are sourced; scores, architecture, effort and product boundaries are recommendations. No physical-device, mobile build, delivery or connectivity test was performed.

## Focused first release

The MVP has four destinations: Attention, Runs, Start and Connection. Connection shows the current host, human principal, verified permissions, last successful refresh and access problems. A small initial catalog matters more than a complex navigation system.

| Task | Phone behavior and release boundary |
| --- | --- |
| Monitor runs | Bounded authorized list and run detail: the existing eight statuses with words and accessible symbols, current step, timestamps, last observed state and relevant transitions. Foreground push plus snapshot recovery. No cost, completion percentage or ETA: ORCA cannot supply them. |
| Pending decisions | Inbox distinguishes durable gates from ephemeral live tool asks. Show exact question, options, consequence, evidence, owner availability and supported actions. Cached or incomplete evidence disables decisions. Live asks are visible/alertable but desktop-only to answer in v1. |
| Safe summaries and artifacts | Server-allowlisted summaries and a bounded text/Markdown artifact view with provenance, version/hash, truncation and sensitivity labels. No remote images, executable HTML, automatic link fetches or untrusted tool output in notifications. Show missing/redacted content honestly and require desktop review when omitted evidence is necessary. |
| Start approved workflows | An administrator-selected catalog of exact workflow versions/revisions and permitted input fields. Show target, declared effects and effective configuration generation; validate on server and explicitly confirm. Use retry-safe direct admission, not arbitrary YAML, shell, unbounded prompt submission or a client-maintained approval flag. Root workflows that edit code need #460 or an equivalently proven isolated execution profile before inclusion. |
| Answer approvals | Initially allowlisted durable choices, one-time only, exact presentation revision, fresh authoritative read and explicit confirmation. Record-only is separate from answer-and-continue. Do not reinterpret a Request changes branch as Reject; protected revision composition remains desktop work. |
| Cancel | Explicit run/host confirmation and consequence statement; ask for fresh user presence when destructive. Show Cancel requested until authoritative state confirms cancellation. Existing operator cancellation needs mobile freshness and uncertainty handling before release. |
| Resume | Only when the server advertises a supported `expectedBoundary` and current execution authority. Use the continuation receipt, not long-running legacy resume. Unsupported roots, children, live callbacks, ambiguous pauses or unavailable generations explain why desktop intervention is required. Include the now-merged #443 fix and retain its regressions. |

Keep workflow/configuration/prompt editing, standing permission grants, arbitrary shell, provider secrets, host installation/update, lease breaking, general recovery, bulk destructive controls, plan authoring, PR publication/merge administration and detailed diff/revision composition on desktop. The phone may display a safe pointer to these tasks. A workflow with release, deployment, external publication or secret access is excluded from the initial approved catalog unless separately reviewed with stronger server policy; a generic workflow name is insufficient evidence of safety.

Multiple hosts/accounts are **schema concerns now, UI work later**. Key cache, credentials, intents and deep links by verified `(workspaceId, principalId, enrollmentId)`; track daemon `instanceId` separately as boot identity. A hostname is not an identity. V1 has one active enrollment and requires explicit disconnect/re-enrollment to switch. Do not merge inboxes, use a default account for an old notification, or make an unknown host active automatically. Later add a host switcher and separate human accounts without changing command identity.

| Notifications, secure storage and future Watch integration | 20 | 5 | 4 | 3 | 3 | 2 |
| Actual ORCA code reuse and existing TypeScript skills | 15 | 2 | 4 | 1 | 5 | 5 |
| Maintenance and testing for a small Apple client | 20 | 4 | 3 | 3 | 3 | 4 |
| Deployment convenience and cross-platform flexibility | 20 | 2 | 4 | 5 | 5 | 5 |

React Native wins this weighting slightly. **SwiftUI is the conditional recommendation if Casey and Cal commit to Apple/Watch integration and a Swift maintainer.** Moving five weight points from platform flexibility to Apple integration gives SwiftUI 3.90 and React Native 3.80; this shows how the product decision changes the result. V1 mirrored alerts alone do not require SwiftUI. If Android is funded within a year, or the team cannot maintain Swift, choose React Native/Expo after the same contract spike. Most safe-remote-control engineering is shared server work whichever framework wins.

## What can actually be reused

The app layering rule remains: clients consume protocol/design, not engine/store. Swift and Dart cannot import TypeScript implementation. React Native is not React DOM. Code sharing should follow this inventory, with extraction tests instead of importing the whole renderer.

| Existing code | Verified coupling | Reuse decision |
| --- | --- | --- |
| [Protocol package](../../../packages/protocol/src/index.ts), [version](../../../packages/protocol/src/version.ts) | Zod schemas/TypeScript types; runtime schema imports use the deliberately Node-free `@orca/core/schemas` surface. No existing Swift/Dart SDK or code generator was found. | TS clients can reuse validated wire schemas after a mobile bundle audit. SwiftUI uses a small typed client and cross-language golden fixtures for exact JSON shapes; evaluate generation later without assuming Zod refinements translate losslessly. Protocol errors, capabilities and strict envelopes must remain equivalent. |
| [React renderer](../../../packages/app/renderer/src/main.tsx), `ui/`, `list/`, `panes.ts` | HTML elements, DOM measurement, CSS variables, keyboard scopes, Electron `window.orca`, fixed split panes | Capacitor/PWA can reuse selected primitives after touch/accessibility redesign. | [Attention model](../../../packages/app/renderer/src/attention/card-model.ts), [notification stream](../../../packages/app/renderer/src/notifications.ts) | Pure TypeScript option/consequence/evidence rules and injected stream filtering, separate from React mounting | Candidate extraction for TS clients; port behavior with shared fixtures in Swift/Dart. Desktop shortcut digits and default selection are not a recommendation for a phone's destructive actions. |
| [Design tokens](../../../packages/design/tokens.json), [semantics](../../../packages/design/semantics.json) | JSON source plus generated CSS/TS; bundled fonts/glyphs and desktop sizes | Reuse status vocabulary, semantic colors and accessible pairing intent. Add reviewed native token generation if needed; do not blindly transplant pixel row heights or custom glyph fonts into Dynamic Type. No design-system edits in this PR. |
| Existing `DaemonClient`, subscriptions and app admission journal | Node credential-file imports; Electron `safeStorage`, filesystem and IPC. Subscription uses global WebSocket with an injectable factory, but shares Node auth and desktop lifecycle assumptions | The wire is reusable; these implementations are not drop-in iOS libraries. Implement URLSession/Keychain transport and protected intent storage. TS alternatives must split browser/native transport from Node auth. |
| Daemon auth, operator projections, admissions, continuation and engine business rules | Authoritative host-side code over leases and protected journals | Reuse on the server through shared services. Never move lease checks, retry admission, workflow evaluation, permission writes or authorization to the phone. Bounded operator reads are a useful starting point, not proof arbitrary output is privacy-safe. |
| Vitest, Playwright/Electron tests and scripted agent | Existing fixtures and assertions, desktop runner | Reuse synthetic server scenarios, protocol vectors and safety invariants. Add Swift unit and XCUITest/device tests; desktop smoke is not mobile acceptance. |

For SwiftUI, budget a **small protocol conformance layer**, not a second business-rule engine. Freeze only the mobile projection/command subset; generate or hand-maintain models with fixtures that fail when server contracts change. Missing capabilities and incompatible major versions explain disabled actions rather than triggering guessed fallback RPCs.

## Native interaction and background behavior

Use system navigation and controls, readable summaries, explicit consequences, large touch targets, Dynamic Type, VoiceOver labels and logical focus order. Include reduced motion, contrast, landscape and compact-device coverage. Status always has a word; announce meaningful transitions, not streamed text. Native defaults help but do not prove accessibility. Do not auto-focus Approve or turn a swipe, keyboard repeat, notification tap or default Watch gesture into a decision.

Every candidate has the same fundamental iOS constraint: the operating system schedules background work. A background task or silent push is not an always-running monitor. Apple describes background notification delivery as discretionary; Expo also delegates scheduled work to BGTaskScheduler. Keep a foreground stream for live views, perform bounded refreshes on open/reconnect, and let the host/APNs sender handle alerts while the app is suspended. [Apple background pushes](https://developer.apple.com/documentation/usernotifications/pushing-background-updates-to-your-app), [Expo background tasks](https://docs.expo.dev/versions/latest/sdk/background-task/).

Offline mode shows a timestamped, minimized cache and unsent drafts. **No automatic offline mutation queue** in v1. Reconnection reads current state and requires renewed confirmation for unsent actions. Sent-but-unconfirmed intents retain their original identity for read-only reconciliation. The phone must remain useful if notification permission is denied, Focus suppresses an alert, or VPN is unavailable. These are explicit product requirements, not guarantees supplied by a framework.

## Long term implications

SwiftUI buys direct Apple integration and a relatively small client dependency set, at the cost of Swift expertise, Apple build hardware and an Android UI rewrite. React Native/Expo reduces future Android UI work but adds framework/Expo/native-module upgrades; local native builds and direct APNs limit hosted-service lock-in. Flutter offers broad rendering portability with a new Dart ecosystem. Capacitor preserves web code but requires ownership of both WebView and native bridges. PWA minimizes store dependence while accepting installation, credential-storage and background limits.

Keep versioned HTTP contracts, portable conformance fixtures, an independently replaceable notification provider and stable host identity. Those boundaries allow a later Android app, RN rewrite or web read client without replacing the daemon or receipts. Avoid a custom cross-platform UI framework, cloud-only identity requirement or proprietary relay SDK in the first release. Moving framework later remains real UI/testing work; shared APIs reduce that cost, not eliminate it.
