- **agents:** an agent with `driver: claude-agent-sdk` runs on an SSH host (#1130). The SDK and ORCA's permission bridge stay on ORCA's machine; only `claude` runs on the host, started over its SSH configuration as the person's own login there, with that machine's Claude Code and sign-in and none of the daemon's environment. Environment values go to the remote shell over the connection's stdin, never a command line, and the host owns the launch: its processes carry a per-launch marker, launch and every stop share one lock and an explicit state so a stop during startup cannot miss it, the host stops them by itself when ORCA's input ends or its heartbeat stops arriving, and every session end also stops them over a new connection, with a cleanup that cannot be confirmed reported as `remote-cleanup-unconfirmed` rather than closure. The host must be Linux with bash and flock. A `claude` that is not signed in there is refused with `claude auth login` guidance that names the host. Every call it makes is a person's to allow (no rule allows one, since ORCA cannot check a directory on that machine); secret references and `nativeToolHook: experimental` are refused there.
