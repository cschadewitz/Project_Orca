- **protocol:** protocol 2.8 adds history paging to `runs.list`: an optional `cursor` and a `nextCursor` on the result, a place in the list's order (creation time, then id) rather than a count, so paging back through history is not shifted by runs started meanwhile. Scoped callers page over the runs they can see.
- **app:** the Runs tree reads history a page at a time and offers **Load older runs** until the store has nothing older (by cursor on a 2.8 daemon, by offset on an older one). A page that answers after the filter changed is dropped. A link to a run no page holds yet reads that one run and opens it.
