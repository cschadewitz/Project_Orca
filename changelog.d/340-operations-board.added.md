- **protocol:** protocol 2.3 adds `outcome`, `workflowId`, `workflowVersion`, `createdFrom` and `createdTo` filters and an opt-in `operations` view to `runs.list` and `runs.get`: last sequence and activity, step counts, the lease owner, and host and usage facets that say `unavailable` rather than zero. A shared run follower keeps several runs current from one notification stream, dropping duplicates, healing gaps with a bounded snapshot re-read, and never letting an older snapshot overwrite a newer status.
- **app:** the Runs surface has a Board view next to the Tree. It follows the active runs the filter shows, live, with their state, step counts, what each is waiting on (an agent slot included), last activity, owner, and whether the card is live, catching up, reconnecting, not current or finished. Choosing a card opens the run in the tree. The filter bar adds a workflow and a start-time filter.
