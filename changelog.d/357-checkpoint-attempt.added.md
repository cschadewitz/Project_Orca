- **engine, cli:** `orca recovery start <runId> [--checkpoint <stepRunId|nodeId>]` starts a checkpoint attempt of a failed run and follows it. The attempt is a new run, linked to its source (`run.checkpoint`, `reusedFrom` on each reused step), that reuses the recorded results, artifacts and vars up to the checkpoint and runs on from there. It uses the source's pinned workflow, recorded configuration, launch inputs and workspace. It goes through retry-safe admission, so `--idempotency-key` returns the same attempt instead of starting another. Only one attempt of a run can be unfinished at a time, and the source run's log is never changed. A refusal (`RECOVERY_BLOCKED`) gives the same reasons as the preview.
