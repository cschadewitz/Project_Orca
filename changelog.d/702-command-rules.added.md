- **core, agents, daemon, app:** Permission rules can match a shell command by its words: `command: "git push"` denies or asks for `git push` however it is written (`git -C repo push`, `sudo git push`, `bash -c "git push"`, or as one part of a compound command), and a final `*` covers a family (`npm *`). A command rule can deny or ask, never allow, because a command's words do not prove what it runs. For the same reason ORCA no longer offers, writes or honours a standing "Always allow" for a shell command: each command is answered once, and earlier title-based allows for commands in the permission sidecar are ignored. The "Always deny" review offers wider command rules (`npm run *`, `npm *`) alongside the exact command, and the Config surface shows and edits the new **Command** field. A config holding a command rule must declare `version: 2`, and a permission sidecar holding one is written as version 3, so ORCA 0.7.x refuses them.
