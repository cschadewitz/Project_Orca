- **app:** the workflow editor's validation panel is bound to the draft's current revision. A late answer never replaces newer findings; while the daemon is away the panel says `Checking` instead of calling the draft clean, and it validates the draft again on reconnecting, on a different daemon, and when the active configuration changes. Publishing waits for that. The live region speaks only when the draft goes between clean and having errors.
- **daemon:** a workflow draft with no active configuration to check against carries one whole-workflow error saying so, rather than looking clean, and a missing start node reports once instead of once more for every node it leaves unreachable. Every rule the panel shows has a fixture draft that produces exactly its row.
